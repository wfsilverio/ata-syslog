Principal achado

Não há como entrar como Gestor ou Fiscal com contratos no Localhost.

  • A entrada simulada grava na sessão o IdPessoa do mock (1001), e o painel consulta a API com esse id. Ele não existe no SISLOG, então o painel fica sempre vazio ("Não há contratos disponíveis para consulta.").
  • O id real desse CPF no SISLOG é 4198102. A simulação recusa a troca do IdPessoa, tanto para esse id quanto para o de um gestor real (2526169, gestor de 16 contratos publicados): "Não foi possível validar o usuário.".
  • O único Fiscal do mock é o cenário negativo "Fiscal sem Telas", e o perfil 104 não está disponível para o usuário Gestor.

Por isso 16 casos ficaram sem executar. Com o painel vazio, as correções desta tarde funcionam:

  • a falha na carga mostra a MSG004 com o texto da análise e Tentar novamente, sem "Ops!";
  • a MSG001 aparece para quem não tem contratos;
  • a pesquisa sem resultado mostra a mensagem de nenhum contrato encontrado.

O que reprova: o indicador Assinatura pendente não é calculado ("A API ainda não informa este indicador.").

Erros de console e rede

  • GET /PainelGestorFiscal/Obter → 200 em 1,2 s, Sucesso: true, 0 contratos.
  • GET /PainelGestorFiscal/Obter?busca=ERRO → 200 com Sucesso: false e "Não foi possível carregar todas as informações do Dashboard. Tente novamente.".
  • Falha simulada (status 0) → tela "O painel não foi carregado", sem "Ops!".

Observações e sugestões

  • Massa: inclua no mock da entrada (CatalogoMockEntradaSislog) um Gestor e um Fiscal cujo IdPessoa seja o de uma pessoa real do SISLOG de homologação. Por exemplo, 2526169, gestor de 16 contratos publicados (159175, 159135, 159184…). O ideal é escolher alguém com contratos que vençam nos próximos 120 dias, para o CT008 e o CT010.
  • Id do usuário de teste: o CPF 04934988181 é a pessoa 4198102 no SISLOG, e não 1001.
  • Cartões com zero: sem contratos, todos os cartões ficam desabilitados. Com contratos, vale conferir se uma faixa com 0 pode ser selecionada, como o CT015 pede.

Condições do teste

  • Entrada pela simulação do SISLOG (cenário gestor). O painel abre como primeira tela.
  • O cache do navegador foi atualizado antes do teste, para carregar os scripts novos.
  • Massa: procurei gestores reais pela aba Equipe dos 26 contratos publicados. O 2526169 é gestor de 16 deles, mas a simulação não aceita entrar com esse id.
  • Falha simulada (CT021 b): com o interceptador de XHR do navegador (status 0 em PainelGestorFiscal/Obter), e também pelo gatilho do próprio painel (busca=ERRO).
  • Página inicial (CT022): pela regra combinada para os testes, o "Definir como tela inicial" não foi acionado.
